# D001 酒馆的承载形态：工作区 + 专用界面

- 状态：已定（方案 A）
- 日期：2026-10-21

## 背景

目标是用 DSHTavern 插件替代 SillyTavern。需要把「酒馆聊天」与普通编码会话分开，并让进入酒馆时整个界面变成聊天应用。最初的想法是：新建一种「酒馆工作区」，其下所有会话都处于酒馆模式。

## 关键事实（来自 DSH 源码调研）

| 事实 | 对方案的影响 |
|---|---|
| Workspace 只是目录注册 `{id, path, title, sessionIds}`，没有 kind 字段，zod schema 封闭 | 不能直接新增工作区类型；酒馆标记要由插件自己维护（sidecar + 目录标记文件） |
| 会话通过在酒馆目录里创建（cwd = workspace.path）归属工作区 | 「工作区下所有会话」天然成立，无需额外分组 |
| Web GUI 没有路由；新增整页界面的官方方式是 `sidebar.panellist` + `main` 主面板 + `ctx.layout.selectPanel` | 酒馆界面可以作为插件主面板，不必改核心 |
| 当前主视图会话可以从 session list 的 `retainedBy.mainView` 推断 | 可以实现「进入酒馆工作区自动切到酒馆界面」 |
| 内置侧栏的工作区行没有插件插槽 | 工作区行徽章需要改 `ui-workspace`，v1 可以不做 |
| 每个会话的视图偏好是浏览器本地存储，没有「按工作区决定默认视图」机制 | 用专用主面板比替换 `conversation.view` 更稳 |

## 候选方案

| 方案 | 描述 | 优点 | 代价 |
|---|---|---|---|
| A 工作区 + 专用酒馆主面板 | 进入酒馆工作区自动切到酒馆面板，离开切回标准对话 | 视觉完全可控；不碰核心；复用会话数据层 | 侧栏仍是 DSH 结构；面板布局要自己做 |
| B 替换会话聊天区 | 用 `conversation.chat.node` / `chat.flow` / `composer` 换皮 | 改动最小；保留 DSH 外壳 | 视觉受限；无法按工作区自动切换视图 |
| C 独立全局酒馆 App | 另起一个独立页面/壳 | 最像独立应用 | 工作区语义消失；集成成本最高 |

## 结论

选 A，并预留「沉浸模式」（折叠侧栏）作为 C 的轻量替代。

### 已确认的默认设定

1. **粒度**：一个酒馆工作区 = 一个酒馆（内含多角色、多聊天、共享世界书与提示词模板）。
2. **自动切换**：进入酒馆工作区/会话时自动切到酒馆面板；用户手动切到标准视图后按会话记忆，不反复抢回。
3. **升级**：允许把已有普通工作区「收编」为酒馆（写入标记文件，需明确确认）。
4. **侧栏徽章**：v1 不做；用酒馆入口 + 面板内的酒馆列表识别，后续再考虑改 `ui-workspace`。

## 原待定项（已由上面的默认设定回答）

1. 一个酒馆工作区 = 一个酒馆（多角色、多聊天、共享世界书）还是一个角色？
2. 进入酒馆工作区是否自动切换界面？手动切换后如何记忆？
3. 是否允许把已有普通工作区「升级」为酒馆？
4. 侧栏工作区徽章 v1 是否放弃？
